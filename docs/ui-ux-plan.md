# DocGenie UI/UX 设计与实施路线

状态：P1 / P2 首轮增量已实现并验证。实现范围见 `implementation.md`，验证记录见 `validation.md`；其余项目仍处于规划阶段。

## 设计原则

1. **正文优先**：限宽居中的阅读列，工具栏降低视觉权重；阅读模式保持克制。
2. **操作分层**：导航管理文件，顶部承接文档与模式，选区浮栏承接文字操作，评论面板承接讨论。
3. **按需展开**：侧栏可收起，窄窗口优先保留正文；隐藏面板不清除当前线程或回复草稿。
4. **真实可用**：只有实现并验证的命令才显示入口；编译通过不等于视觉与交互验收通过。
5. **授权明确**：评论、打开面板与模型输出本身不构成授权。单条「问 AI」与全局默认自动修改都应有准确说明。
6. **原生与本地优先**：继续采用 Makepad + Octoscript + Rust，不用 WebView 替代原生编辑，Markdown 是正文真值。

## 当前工作台

- 左侧真实文件树，主新建入口与 ⌘O 文档跳转；顶部保留最多 6 个文档标签。
- 正文最大 760 Makepad 逻辑点，居中排版，标题 28pt；作者与修改提示同一行，revision 降到页脚。
- 编辑 / 阅读两种模式，保持 Markdown Live Preview：活动单元展示源码，其余单元渲染。
- 右侧大纲 / 评论文字页签；阅读模式大纲跳转不强制切换到编辑模式。
- 评论提供线程摘要、未解决 / 已解决筛选、解决 / 重开、当前线程消息与独立回复草稿。
- 原生选区浮栏与就地评论弹窗已经存在；空白提交禁用，提交是否外发由明确授权决定。
- 760–1099 宽度且评论打开时隐藏导航，低于 760 隐藏两侧。自动隐藏不覆盖用户布局意图。

## 编辑能力与 UI 的边界

工作台排版、图标、面板和评论组织属于视图工程。连续跨块选区、源码与渲染范围映射、中文 IME、稳定 caret 与共享撤销栈属于编辑器工程，不能只靠样式调整完成。

当前文字批注与 Agent replacement 以完整 Markdown 结构块为单位。将来若增加精确 inline 高亮，必须让视觉范围与实际修改 / 外发范围一致，不能用局部高亮误导授权。

主要模块：

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 工作台、受限命令与流程编排 |
| `workspace.rs` | 限宽、窗口尺寸与窄窗口策略 |
| `thread_list.rs` | 从 Workbench 派生只读线程摘要 |
| `discussion.rs` | 当前线程消息卡片 |
| `context_menu.rs` | 选区浮栏与就地评论输入 |
| `live_editor.rs` | 原生 Markdown 编辑与选区 |
| `reading.rs` / `markdown.rs` / `typography.rs` | 块级阅读、媒体与统一排版 |

核心锚点语义改动需同步 `document-core` 回归；新增持久历史需单独设计 `project-store` 存储。

## 分阶段路线

### P1：工作台和设计系统

已实现：限宽正文、标题层级、导航主动作、模式与页签、保存 / revision 信息层级、窄窗口策略。

待做：App-owned tokens / 组件进一步统一、文件条目更多菜单、长标题换行、状态工具提示和键盘焦点完善。保留 vault、标签、⌘O、自动保存与权限契约。

验收：编辑 / 阅读与左右栏组合、长标题、多个窗口尺寸、同尺寸合成文本截图、保存失败反馈。不能只看 widget 状态。

### P2：评论体验

已实现：线程概览、未解决 / 已解决数量和空状态、稳定 thread ID、解决 / 重开、逐线程回复草稿。就地 composer 沿用现有实现，并完善空白提交与授权提示。

待做：线程级等待 / 失败 / 取消状态，紧凑引用与回复组织，同段多线程快捷定位。完整多线程内联回复卡片须先验证长列表性能，不承诺一轮完成。

验收：原文与线程定位、同段多线程、解决 / 重开、过期锚点 / 显式重绑、Escape / 滚动 / 外部点击关闭、草稿隔离。Agent 状态不等于内容已修改。

### P3：有限 Markdown 编辑命令

对现有选区命令进行真实功能和回归审计，再增加 Markdown 可往返的块级命令：标题、列表、引用、代码块等。顶栏与浮栏共用受限 Rust command，不能绕过 Workbench、revision 或 undo。

不承诺任意富文本粘贴、文字颜色或复杂格式持久化。验收覆盖 Unicode 边界、保留焦点 / selection、重复 toggle、undo、评论冲突与保存。

### P4：原生编辑器专项

先用原型验证连续 source selection、跨单元鼠标 / Shift 扩展、source ↔ rendered range、caret / IME / 撤销、滚动锚点与长文虚拟化，再决定 LiveEditor 重构范围。

精确文字批注与整块 replacement 应分开建模。回归覆盖重复文字、格式标记、跨块、重叠线程和迟到结果拒绝。保持 Markdown 真值，不引入 WebView 编辑器。

### P5：可选版本与扩展块

历史快照、diff 与恢复属于新增能力：先约定存储限额、恢复 revision 与线程行为，再实施。块移动、slash menu、复杂表格编辑、公式与图形块单独排期，不属于首轮验收条件。

## 验收材料与产品范围

使用不含私人内容的合成测试文档：长标题、中文换行、重复段落、列表、链接、代码、图片和多个线程。GUI 使用 makepad-test 独立隐藏实例与临时 vault，结束退出自己启动的进程。Mock、真实服务与人工验收分开记录。

不引入多人协作、云端文档真值、共享权限、多页存储抽象、账户系统、小程序或 AppCard。任何新 Agent 请求仍须用户授权，模型输出不是写入许可。

完成每个增量后同步实施 / 架构 / 验证文档，不把首轮交付写成整个路线完成。
